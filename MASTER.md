# TREDIE

## Product

Build Tredie, a polished consumer application where every Stellar transaction creates a unique AI generated collectible creature.

Domain:

tredi.life

Tagline:

Your transactions, alive.

Core idea:

A user makes a transaction through Stellar.

The transaction is verified.

The transaction value determines the rarity.

The rarity determines the creature species.

The system randomly selects visual attributes.

An AI image generation model creates the creature.

The creature is revealed to the user.

The creature is permanently added to their Tredie collection.

The experience should feel magical, simple and emotional.

The user should think:

"I made a transaction and something was born."

The blockchain should mostly disappear into the experience.

Do not make Tredie feel like a crypto dashboard.

Do not make Tredie feel like a banking application.

Do not make Tredie feel like an NFT marketplace.

Do not make Tredie feel like a DeFi application.

Do not make Tredie feel like a financial analytics platform.

Tredie is a beautiful collectible consumer product powered by Stellar.

## Rarity system

Transaction value determines the rarity pool.

Initial rarity ranges:

$0.01 to $9.99

$1,000+

The exact rarity within an eligible pool should be randomly selected according to configurable probabilities.

Keep the rarity configuration centralized so it can easily be adjusted without rewriting the application.

Higher transaction values must provide access to higher rarity creatures.

Never guarantee a specific creature unless the configured rarity rules explicitly do so.

The user never chooses their creature.

The surprise is part of the product.

## Technical implementation principle

Separate the system into clear services.

Transaction service:

Determines whether a Stellar transaction is valid.

Rarity service:

Determines rarity from transaction amount.

Creature service:

Maps rarity to species and selects structured attributes.

Generation service:

Transforms structured attributes into an AI image.

Persistence service:

Stores the Tredie and its metadata.

UI:

Presents the experience.

This architecture should make it easy to replace the image generation provider later.
